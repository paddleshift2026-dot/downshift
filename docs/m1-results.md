# M1 결과 — 사운드 엔진

측정: 2026-11-03, Pleos Connect v2.1 에뮬레이터(Android 14, user 빌드, 앱은 user 10), 브랜치 `feature/m1-sound`. 계획은 `현기차_경진대회/.claude/plans/downshift-m1.plan.md`. 원본 수치는 `docs/m1/` (`latency.txt`, `cpu.txt`, `cpu_top.txt`, `renders_inventory.md`).

상태: 엔진·믹서·입력·화면·측정 완료. 같은 날 오후, 음원이 없을 때의 기본 소리를 **실시간 펄스 합성**으로 바꿨다(아래 절). **남은 일:** 사용자 청음 판정, 구매 음원과의 비교(Task 13, 음원은 이제 선택).

## 무엇이 되나

- 페달·차속·기어로 움직이는 가상 파워트레인: 시동(크랭킹 → 1.6×공회전 플레어 → 안정), 정차 레브와 리미터 바운스, 1단 출발 슬립, 자동·DCT·수동 블립 변속, 킥다운, 오버런
- 소리: rpm 구간 루프를 부하에 따라 on/off로 등전력 크로스페이드, 터보 휘슬·블로오프, 슈퍼차저 윙, 배기 3종(바이쿼드 EQ + 소프트 클립), 감속 팝콘, DCT 변속 팝·수동 다운시프트 블립, 시동·시동 끄기 원샷
- 실시간 합성(기본, 직4·V8·V12): 음원 없이 점화 순서대로 배기 펄스를 합성한다. 구매 음원은 `tools/pack_builder.py`로 `.dsa`(난독화 PCM)로 바꿔 `assets/engines/<id>/`에 넣으면 그쪽을 쓴다(저장소엔 넣지 않음). 미리 구운 루프 합성 팩(`SynthPack`)은 비교용으로 남겼다
- 에뮬레이터 시연: Virtual Console 페달(슬라이더·G29)을 밟으면 엔진음이 반응하고, 앱이 계산한 속도를 콘솔에 되써서 계기판 속도도 따라온다
- 사운드 랩 화면(개발용, 첫 탭)과 adb 명령(`start`·`stop`·`build`·`throttle`·`record`), `tools/sound.sh`(시나리오 녹음·지연·CPU)

## 실시간 합성 (11/03 오후, realenginesimulator.com 조사 뒤)

realenginesimulator.com은 녹음 음원을 하나도 받지 않는다. 브라우저 AudioWorklet이 물리 시뮬레이션(Wiebe 열방출, 240Hz) 값으로 실린더마다 배기 펄스를 쏘고, 코드로 만든 약 0.1초 임펄스 응답을 컨볼루션으로 입힌다(오디오 노드 기록, 음원 요청 0건). 코드는 가져오지 않았고, 공개된 설계 아이디어만 우리 방식으로 다시 만들었다.

**우리 모델** (`core/synth/EngineVoice.kt`, `FiringPlan.kt`)
- 크랭크 각을 샘플마다 적분하고, 점화 순서·뱅크(`FiringPlans`)에 따라 실린더가 자기 각도를 지날 때 펄스를 하나 쏜다. 음정은 점화 주파수 그대로이고, 배기 공명은 rpm과 상관없이 제자리에 있다. 구운 루프는 재생 속도를 바꾸면 공명까지 같이 움직였다
- 펄스: 1ms 안에 솟고 지수로 사라지는 압력 펄스. 부하가 크면 크고 밝다(공회전이 묻히지 않게 바닥 30%). 펄스 길이는 rpm이 오를수록 짧아진다(배기 밸브가 크랭크 각으로 열리므로)
- 사람 같은 흔들림: 사이클마다 세기 ±4~12%, 타이밍 ±0.04ms, 실린더마다 고정 편차(세기 ±3%, 타이밍 ±0.06ms)
- 배기 경로: 실린더별 러너 길이 차이, 뱅크별 경로 차이(V8 0.6ms, V12 0.25ms), 꼬리관 반사(되먹임 콤, 열린 관처럼 반전 −0.15~−0.4), 몸체 공명 3개(피킹 EQ). 크로스플레인 V8은 뱅크마다 점화 간격이 고르지 않아(270·180·90·180°) 둥둥거림이 저절로 생긴다
- 난류: 펄스에 노이즈를 곱해(링 변조) 거친 결을 더하되, 펄스열이 음정을 쥐도록 깊이는 12~30%
- 배기 부품: 순정은 반사가 약하고 둔함, 트랙은 반사가 세고 밝음. 바꾸면 경로를 2,048샘플 동안 교차 페이드
- 엔진이 스스로 내는 순간: 크랭킹(스타터 소리, 릴레이 40ms 뒤 + 압축 펄스), 시동 플레어(rpm이 공회전으로 내려올 때까지 진하게), 리미터의 연료 차단(펄스가 끊기는 소리), 시동을 끈 뒤 크랭크가 잦아드는 소리
- 빠진 것: 연소·기체 역학 계산, 컨볼루션(피킹 EQ 3개로 대신), 흡기 펄스 소리, 밸브 소음

**측정**
- 오디오 스레드 CPU: 처음 6.0% → 울리는 펄스만 도는 구조로 4.5% (구운 루프 3.9%)
- 레브/공회전 RMS 비: 직4 2.53, V8 2.38, V12 2.64 (구운 루프 2.68 / 2.07 / 1.95)
- 테스트 26개 추가(펄스 음성 10, 점화 계획 3, 디렉터 5, 믹서 1, 팩 2, 시나리오 3, 파워트레인 2)

### 지글거림 줄이기 (사용자 청음: "너무 지글거리고 인공적")

사이트의 직4 출력을 브라우저에서 바로 분석해(AnalyserNode, 32768점 FFT, 1/3옥타브) 기준으로 삼았다. 같은 방법으로 우리 녹음을 쟀더니, 리미터 부근에서 점화 주파수 대비 2~8kHz가 13~20dB 셌고 그 대역이 음정 없는 잡음이었다.

| 원인 | 고친 것 |
|---|---|
| 펄스가 0.06~0.2ms에 날카롭게 솟음 (사이트는 약 1ms) | 제곱 상승으로 공회전에서 약 1ms에 솟게, 고회전에서도 0.11~0.17ms보다 빠르지 않게 (고역이 옥타브당 18dB로 떨어짐) |
| 난류 노이즈가 깊고(12~30%) 4.5kHz까지 | 깊이를 줄이고 1.4kHz까지만 |
| 꼬리관 반사가 모든 주파수에서 같은 세기로 울림 (금속성) | 왕복마다 고음이 줄어드는 반사, 배기 부품별 머플러·실내 저역 통과, 직류 차단 |
| 펄스 날을 감싸는 울림이 없음 (사이트는 0.1초 컨볼루션) | 지연선 4개짜리 짧은 몸체 울림(약 90ms) |
| 팝콘이 1.5~6kHz 노이즈 버스트 | 낮은 '퍽'(70~130Hz) 위에 어두운 크랙, 터보·슈퍼차저·블로오프 음량도 낮춤 |

에뮬레이터 녹음(`*_rt2.wav`) 리미터 구간에서 2/4/8kHz가 직4 순정 9/18/35dB, V8 터보 10/9/12dB 줄었고, 감속 팝콘 구간도 V8 4/4/8dB, V12 7/10/13dB 줄었다. 시나리오 CPU는 19.2·18.7%(오디오 스레드 5.1%).

## 에뮬레이터에서 새로 확인한 것

| 내용 | 근거 | 결정 |
|---|---|---|
| 콘솔은 속도를 **정수 km/h로만** 받는다 (`speed=30.5` → 400 `invalid_speed`). 쓰기 응답은 차량 상태 전체(약 13KB)이고, 모든 응답이 `Connection: close`라 연결을 재사용할 수 없다 | curl | 속도는 정수로 최대 5Hz 쓰기, 폴링은 소켓 직접 요청 |
| **주행 중에는 Pleos 홈 화면이 앱 화면을 가린다.** 차가 움직이면 UX 제한(0x50: NO_VIDEO·NO_SETUP)이 켜지고 `TaskViewContainer(com.downshift.app) updateDrivingRestrictionRegion`이 앱 영역에 "주행 중에는 사용할 수 없습니다"를 띄운다. 홈 화면 로그는 우리 액티비티를 `distractionOptimized: true`로 인식한다. 앱은 resumed 상태이고 **엔진음은 계속 난다** | logcat, 화면 캡처 | 소리에는 지장 없음. 주행 중 앱 화면을 보여 줄 수 있는 조건은 사무국 문의에 추가, M3 주행 화면 설계에 반영 |
| Pleos Vehicle SDK를 초기화하면 **메인 스레드가 1코어의 약 7%를 계속 쓴다** (초기화만 빼면 0.5% 미만) | 스레드별 top | 사운드 엔진은 브레이크를 쓰지 않으므로 기본으로 끔(`CarSignalsAdapter(usePleosBrake)`). 방향지시등 등 Pleos 기능이 필요한 M3에서 필요할 때만 초기화 |
| 화면 한 프레임이 18~48ms 걸린다 (소프트웨어 렌더링, 버벅인 프레임 62%) | `dumpsys gfxinfo` | 실시간 계기는 그리기 단계에서만 값을 읽고 5Hz로 갱신. M3 주행 화면도 같은 방식 |
| 출력 기본 레이트는 48kHz다 | `PROPERTY_OUTPUT_SAMPLE_RATE` | AudioTrack을 48kHz로 열고 44.1kHz 팩은 믹서에서 리샘플링(FAST 경로 유지) |

## 계획과 달라진 점

| 계획 | 실제 | 이유 |
|---|---|---|
| 1단 슬립이 속도 8m/s까지 공회전 쪽으로 사라짐 | 바퀴 rpm이 따라올 때까지 슬립 rpm 유지 | 섞는 방식은 출발 도중 rpm이 2,500 → 1,600으로 꺼졌다 다시 올랐다(스펙트로그램 V자). 짐 진 엔진처럼 들림 |
| 합성 팩 구간 음량 같음 | 구간이 높을수록 커짐 (공회전 = 최고 구간의 55%) | 레브가 공회전보다 1.15배밖에 안 커서 녹음 음원처럼 바꿈 (V8 2.07배) |
| — | 스타터는 릴레이 지연 40ms 뒤에 돈다 | 시동 버튼 전 무음 보장, 실제 차와 같음 |
| AudioTrack = 팩 샘플레이트(44.1kHz) | 기기 기본 레이트(48kHz), 클립은 믹서에서 리샘플링 | 레이트가 다르면 저지연 경로를 못 받을 수 있음 |
| master가 믹스 전체에 곱해짐 | 원샷은 자기 게인으로 끝까지 재생 | 시동을 끈 다음 블록에서 master가 0이 되면 시동 끄기 소리가 잘림 |
| — | 시동 원샷이 나오는 동안(레브 전) 루프는 쉼 | 크랭킹 중 루프가 0.5배속으로 겹쳐 들림 |
| 콘솔 20ms 폴링, 연결 재사용 | 시동 중 30ms, 꺼짐 100ms, 소켓 직접 요청 | 콘솔이 매번 연결을 닫아 재사용 불가. 20ms는 폴링만 1코어의 11%, 30ms는 7.7% (지연 최대 91ms로 목표 안) |
| 앱은 AAOS 차속만 받음 | 시연은 앱이 계산한 50Hz 속도를 직접 쓰고 AAOS 차속은 계기판용. 실차용으로 `SpeedSmoother`(0.1초 지연) 추가 | AAOS 차속은 1km/h 단위로 약 10Hz라 1단에서 rpm이 100ms마다 약 108rpm(반음)씩 계단처럼 뜀 |
| 화면 10Hz | 5Hz, 그리기 단계 갱신 | 메인 스레드 24% → 4.8% |
| Pleos 브레이크 연결 | 기본 끔 | 위 측정. 시연 브레이크는 콘솔 값 |
| 에뮬레이터 녹음 WAV 커밋 | `.gitignore` (`sound.sh scenario`로 다시 만듦) | 파일당 2.5MB |
| 음원이 없을 때 구운 루프 합성 팩 | 실시간 펄스 합성 (사용자 결정) | 공명이 음정을 따라 움직이지 않고, 리미터·크랭킹·시동 끄기가 엔진 모델에서 나옴. PRD 제외 사항을 고침 |
| 콘솔 30ms 폴링 | 페달이 2초 넘게 그대로면 40ms | 실시간 합성의 오디오 비용만큼 CPU 여유 확보. 최악 지연 최대 98ms |
| 계기는 값이 바뀌면 다시 그림 | 보이는 자릿수로 반올림해 같으면 안 그림 | 정속·공회전 때 화면 갱신이 멈춤 |

- 스펙트로그램으로 확인한 것: 시동 플레어, 리미터 바운스, 기어별 rpm 상승과 변속, 발을 뗀 뒤 팝, 브레이크 중 다운시프트(수동은 블립), 시동 끄기. 블록 경계 이음새 없음(경계와 내부의 샘플 변화량 평균이 같음)
- 구매 음원은 이제 선택이다. 실시간 합성과 같은 시나리오로 들어 보고 엔진별로 정한다

## 남은 일과 M2로 넘기는 것

1. 사용자: 실시간 합성 청음 → 판정(고칠 점이 있으면 음색 조율). 음원은 비교가 필요할 때만 구매 → `audio_test/pack/` → Task 13. 4번째 엔진은 실시간 합성이면 음원 없이 추가할 수 있다(점화 순서·뱅크·음색만 정하면 됨)
2. 사무국 문의(사용자 발송): 가속 페달 신호, Music/Audio 카테고리에 더해 **주행 중 앱 화면 노출 조건**(홈 화면이 가림)
3. M2 개러지: 부품·슬라이더는 `Build`와 `SoundLabViewModel.setBuild` 그대로 쓴다. 엔진 전환 때 합성 팩 생성 지연(최대 약 1초)은 미리 만들어 두거나 캐시
4. M3 주행 화면: 주행 중 가림 정책 확인 전까지 소리 중심으로 설계, 갱신은 그리기 단계·저빈도. Pleos SDK는 필요할 때만 초기화
