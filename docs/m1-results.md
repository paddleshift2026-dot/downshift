# M1 결과 — 사운드 엔진

측정: 2026-11-03, Pleos Connect v2.1 에뮬레이터(Android 14, user 빌드, 앱은 user 10), 브랜치 `feature/m1-sound`. 계획은 `현기차_경진대회/.claude/plans/downshift-m1.plan.md`. 원본 수치는 `docs/m1/` (`latency.txt`, `cpu.txt`, `cpu_top.txt`, `renders_inventory.md`).

상태: 엔진·믹서·입력·화면·측정 완료. **남은 일:** 사용자 청음 판정, 구매 음원 연결(Task 13, 음원 구매 대기).

## 무엇이 되나

- 페달·차속·기어로 움직이는 가상 파워트레인: 시동(크랭킹 → 1.6×공회전 플레어 → 안정), 정차 레브와 리미터 바운스, 1단 출발 슬립, 자동·DCT·수동 블립 변속, 킥다운, 오버런
- 소리: rpm 구간 루프를 부하에 따라 on/off로 등전력 크로스페이드, 터보 휘슬·블로오프, 슈퍼차저 윙, 배기 3종(바이쿼드 EQ + 소프트 클립), 감속 팝콘, DCT 변속 팝·수동 다운시프트 블립, 시동·시동 끄기 원샷
- 합성 엔진 팩(직4·V8·V12): 구매 음원 없이 끝까지 동작. 구매 음원은 `tools/pack_builder.py`로 `.dsa`(난독화 PCM)로 바꿔 `assets/engines/<id>/`에 넣으면 자동으로 그쪽을 쓴다(저장소엔 넣지 않음)
- 에뮬레이터 시연: Virtual Console 페달(슬라이더·G29)을 밟으면 엔진음이 반응하고, 앱이 계산한 속도를 콘솔에 되써서 계기판 속도도 따라온다
- 사운드 랩 화면(개발용, 첫 탭)과 adb 명령(`start`·`stop`·`build`·`throttle`·`record`), `tools/sound.sh`(시나리오 녹음·지연·CPU)

## 에뮬레이터에서 새로 확인한 것

| 내용 | 근거 | 결정 |
|---|---|---|
| 콘솔은 속도를 **정수 km/h로만** 받는다 (`speed=30.5` → 400 `invalid_speed`). 쓰기 응답은 차량 상태 전체(약 13KB)이고, 모든 응답이 `Connection: close`라 연결을 재사용할 수 없다 | curl | 속도는 정수로 최대 5Hz 쓰기, 폴링은 소켓 직접 요청 |
| **주행 중에는 Pleos 홈 화면이 앱 화면을 가린다.** 차가 움직이면 UX 제한(0x50: NO_VIDEO·NO_SETUP)이 켜지고 `TaskViewContainer(com.downshift.app) updateDrivingRestrictionRegion`이 앱 영역에 "주행 중에는 사용할 수 없습니다"를 띄운다. 홈 화면 로그는 우리 액티비티를 `distractionOptimized: true`로 인식한다. 앱은 resumed 상태이고 **엔진음은 계속 난다** | logcat, 화면 캡처 | 소리에는 지장 없음. 주행 중 앱 화면을 보여 줄 수 있는 조건은 사무국 문의에 추가, M3 주행 화면 설계에 반영 |
| Pleos Vehicle SDK를 초기화하면 **메인 스레드가 1코어의 약 7%를 계속 쓴다** (초기화만 빼면 0.5% 미만) | 스레드별 top | 사운드 엔진은 브레이크를 쓰지 않으므로 기본으로 끔(`CarSignalsAdapter(usePleosBrake)`). 방향지시등 등 Pleos 기능이 필요한 M3에서 필요할 때만 초기화 |
| 화면 한 프레임이 18~48ms 걸린다 (소프트웨어 렌더링, 버벅인 프레임 62%) | `dumpsys gfxinfo` | 실시간 계기는 그리기 단계에서만 값을 읽고 5Hz로 갱신. M3 주행 화면도 같은 방식 |
| 출력 기본 레이트는 48kHz다 | `PROPERTY_OUTPUT_SAMPLE_RATE` | AudioTrack을 48kHz로 열고 44.1kHz 팩은 믹서에서 리샘플링(FAST 경로 유지) |

## 계획과 달라진 점

| 계획 | 실제 | 이유 |
|---|---|---|
| 1단 슬립이 속도 8m/s까지 공회전 쪽으로 사라짐 | 바퀴 rpm이 따라올 때까지 슬립 rpm 유지 | 섞는 방식은 출발 도중 rpm이 2,500 → 1,600으로 꺼졌다 다시 올랐다(스펙트로그램 V자). 짐 진 엔진처럼 들림 |
| 합성 팩 구간 음량 같음 | 구간이 높을수록 커짐 (공회전 = 최고 구간의 55%) | 레브가 공회전보다 1.15배밖에 안 커서 녹음 음원처럼 바꿈 (V8 2.07배) |
| — | 스타터는 릴레이 지연 40ms 뒤에 돈다 | 시동 버튼 전 무음 보장, 실제 차와 같음 |
| AudioTrack = 팩 샘플레이트(44.1kHz) | 기기 기본 레이트(48kHz), 클립은 믹서에서 리샘플링 | 레이트가 다르면 저지연 경로를 못 받을 수 있음 |
| master가 믹스 전체에 곱해짐 | 원샷은 자기 게인으로 끝까지 재생 | 시동을 끈 다음 블록에서 master가 0이 되면 시동 끄기 소리가 잘림 |
| — | 시동 원샷이 나오는 동안(레브 전) 루프는 쉼 | 크랭킹 중 루프가 0.5배속으로 겹쳐 들림 |
| 콘솔 20ms 폴링, 연결 재사용 | 시동 중 30ms, 꺼짐 100ms, 소켓 직접 요청 | 콘솔이 매번 연결을 닫아 재사용 불가. 20ms는 폴링만 1코어의 11%, 30ms는 7.7% (지연 최대 91ms로 목표 안) |
| 앱은 AAOS 차속만 받음 | 시연은 앱이 계산한 50Hz 속도를 직접 쓰고 AAOS 차속은 계기판용. 실차용으로 `SpeedSmoother`(0.1초 지연) 추가 | AAOS 차속은 1km/h 단위로 약 10Hz라 1단에서 rpm이 100ms마다 약 108rpm(반음)씩 계단처럼 뜀 |
| 화면 10Hz | 5Hz, 그리기 단계 갱신 | 메인 스레드 24% → 4.8% |
| Pleos 브레이크 연결 | 기본 끔 | 위 측정. 시연 브레이크는 콘솔 값 |
| 에뮬레이터 녹음 WAV 커밋 | `.gitignore` (`sound.sh scenario`로 다시 만듦) | 파일당 2.5MB |

추가 테스트: 믹서 리샘플링(44.1kHz 클립이 48kHz에서 음정·길이 유지), `GearState.fromAaos`, `SpeedSmoother`.
