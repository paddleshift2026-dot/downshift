# M3 결과 — 주행·안전·결산

측정: 2026-11-03, Pleos Connect v2.1 에뮬레이터(Android 14, user 빌드, 앱은 user 10, 앱 창 1682×1210, density 1.0), 브랜치 `feature/m3-drive`. 계획은 `현기차_경진대회/.claude/plans/downshift-m3.plan.md`. 원본 수치와 캡처는 `docs/m3/`(`trip.txt`, `persist.txt`, `cpu.txt`, `music.txt`, `navi.txt`, `sound_check.txt`, `memory.txt`, `01`~`10` 캡처)에 있다. 재현은 `bash tools/drive.sh flow|trip|persist|cpu|music`.

상태: 계획한 14개 작업을 마쳤다. **남은 일:** 사용자 확인(화면·소리), 실차에서만 볼 수 있는 것(아래 "확인하지 못한 것").

## 무엇이 되나

- **첫 실행 안전 안내:** 네 가지 약속과 동의 체크가 있고, 동의해야 개러지로 간다. 세팅 탭의 "안전 안내 다시 보기"로 다시 볼 수 있다. 동의 버전이 올라가면 다시 묻는다.
- **시동 화면:** 개러지의 "이 빌드로 시동"이 이 화면을 연다.
  - rpm 게이지(빨간 구간은 엔진 레드라인 + 세팅 오프셋, V12는 0~9)와 엔진 렌더, 번호판, 점화 순서가 보인다.
  - START를 0.9초 누르면 링이 차고 시동이 걸린다. 게이지가 한 번 끝까지 쓸고 내려오고 엔진이 살짝 튄다.
  - 레브하면 기울고 불빛이 나며, 떼면 팝 불빛이 난다. STOP은 눌러서 끈다.
  - 시연 버튼은 "가속 페달 누르기"(콘솔 가속 85%)와 "기어 D".
- **P↔D 자동 전환:** 기어가 D·R이 되면 주행 기록이 시작되고 주행 화면이 뜬다. P로 돌아오면 정산하고 결산 화면을 띄운다. 100m 미만이면 결산 없이 원래 화면으로 돌아간다.
- **주행 화면:**
  - 이번 주행 포인트 링이 주행을 시작할 때 정한 목표 부품을 향해 찬다("V12 해금 가능" / "터보 Stage 3까지 222 P").
  - 멈춘 엔진 렌더, 번호판, 상황 칩, 화면 폭 음소거 버튼이 있다.
  - rpm·속도·기어는 없다. 값은 바뀔 때만 바로 교체하고 애니메이션은 없다.
- **안전 주행 포인트:**

  | 항목 | 규칙 |
  |---|---|
  | 거리 | 5P/km |
  | 제한속도 이하로 달린 거리 | +1P/km |
  | 스쿨존·단속 카메라·구간 단속을 지킴 | +6P/곳 |
  | 회전 30m 전(IC·휴게소 100m)부터 같은 쪽 지시등 | +0.5P/회 |

  - 항목별로 반올림한 뒤 더한다. 감점은 없다.
  - 결산 때 한 번에 지갑에 넣는다. 주행 중에는 10초마다 체크포인트를 남긴다.
- **상황 인지 볼륨:**

  | 상황 | 엔진음 | 칩 |
  |---|---|---|
  | 안내 음성·통화·알람 | −12dB, 끝난 뒤 0.8초 유지 | 안내 음성 · 잠시 줄임 |
  | 스쿨존 100m 전부터, 조용 구간 | −10dB | 스쿨존 · 엔진음 줄임 |
  | 동승자 | 상한 40% | 동승자 · 볼륨 40% |
  | 음소거 | 0 | 음소거됨 |

  - 내려갈 때 0.15초, 올라올 때 0.6초에 걸쳐 바뀐다.
- **결산:** 포인트 카운트업, 거리·준수율·잔액, 항목 넷, 제한속도 정보가 없던 거리 안내, 다음 해금 카드(남은 P·km), 지금 해금할 수 있는 부품, "개러지에서 해금하기".
- **앱이 꺼졌을 때:** 주행 중 강제 종료되면 다시 열 때 이어 간다. 정차 중 체크포인트가 남아 있으면 한 번만 정산하고 결산을 띄운다.
- **신호의 실제 경로:**
  - 방향지시등·주행계·좌석은 Virtual Console → Pleos Vehicle SDK로 받는다. 시동 중이거나 주행 중일 때만 켜고, 둘 다 아니면 5초 뒤 끈다.
  - 제한속도·카메라·주의구간·회전 안내는 NaviHelper로 받는다.
  - 안내 음성은 재생 콜백으로 감지한다. 시연 차가 0.1km 갈 때마다 콘솔 주행계를 움직인다.
- **adb:** `drive --es event agree|screen|limit|camera|section|school|turn|quiet|guide|music|mute|lapse|pleos|route`(시연·점검용, `DemoBus.kt` KDoc). 제한속도 0만 보내는 에뮬레이터 내비 대신 adb로 넣는 제한속도는 0으로 지울 때까지 남는다.

## 계획과 달라진 점

| 계획 | 실제 | 이유 |
|---|---|---|
| 좌석 콜백은 한 박자 늦으니 다시 읽음 | **콘솔과 값이 반대로 읽힌다.** 콘솔에서 좌석을 다 비우면 SDK는 모두 앉았다고 하고, 앉히면 비었다고 한다. 다시 읽어도 같다. 콘솔이 붙어 있을 때만 뒤집어 읽고, 실차에서는 SDK 값을 그대로 쓴다 | M0의 "한 박자 늦음"은 반전을 잘못 본 것이었다 (`navi.txt`) |
| 내비 제한속도와 adb 제한속도가 같은 값 | adb 값을 따로 두고, 0으로 지울 때까지 남긴다 | 에뮬레이터 내비가 0을 계속 보내서 adb 값을 바로 지웠다 |
| `DriveEvent`는 DriveHost.kt 안 | 자기 파일(`DriveEvent.kt`) | 어댑터(Task 8)가 호스트(Task 9)보다 먼저 컴파일돼야 했다 |
| `EngineHost.console(cmd)` | `EngineHost.demo(cmd)` | 콘솔 필드 이름과 겹침 |
| 길안내 취소 없음 | adb `drive --es event route --es value cancel` | 에뮬레이터 경로는 차가 움직이지 않아 700m 앞 회전이 계속 남는다. 시연 주행이 그 회전을 판정하지 않게 지운다 |
| 시동 화면의 길게 누르기는 HoldButton 그대로 | 제스처만 떼어 냄(`holdGesture`). 버튼이 손가락 밑에서 사라져도 "누르는 중"이 풀리게 `finally` 추가 | START가 STOP으로 바뀐 뒤 "계속 누르고 있어요"가 남던 버그 |
| 정차 중 남은 체크포인트는 정산만 | 정산하고 결산 화면을 띄운다 | 사용자가 그 주행의 포인트를 볼 수 있게 |
| 개러지 VM의 start()/stop() | 없앰. 시동·정지는 시동 화면에서만 | 시안의 흐름 |

## 확인하지 못한 것

- 실차 내비 이벤트: 제한속도 값, 단속 카메라, 스쿨존 주의구간은 에뮬레이터에서 오지 않는다. 회전 안내만 왔다(거리 단위 m)
- 차량 경고음: 시스템 용도라 앱에 보이는지 모른다. 안내 음성·통화·알람만 처리한다
- 실차 좌석 값: 반전은 콘솔에서만 쟀다
- 음악: 다른 음악 앱으로는 확인하지 못했다(에뮬레이터 음악 앱에 콘텐츠가 없음). 같은 프로세스의 미디어 플레이어로만 확인했다
- 시동·주행·결산의 1칸(세로) 레이아웃: 코드는 있지만 에뮬레이터 창이 넓다
- 주행 중 화면: 차가 움직이면 Pleos 홈 화면이 앱을 가린다(M1과 같음). 주행 화면은 D 정차 때만 보인다
- 앱이 뒤로 갔을 때: 포그라운드 서비스가 없어 프로세스가 정리될 수 있다. 체크포인트 덕에 포인트는 남는다
- TalkBack: 라벨은 달았지만 들어 보지 않았다

## 남은 일과 M4로 넘기는 것

1. 사용자: 첫 실행·시동·주행·결산 화면과 소리 확인
2. M4 시연 모드: 시연 버튼, 개발용 줄, 시연 배속(지금은 adb)을 설정 뒤로 숨긴다. 시연 포인트는 실제 잔액과 따로 둔다(PRD 기능 G)
3. M4: 미디어 재생 포그라운드 서비스 검토 (앱이 뒤로 가도 엔진음과 기록 유지)
4. 도구: adb `garage` 명령은 개러지 화면을 한 번 연 프로세스에서만 먹는다(뷰 모델이 받음). `drive.sh`는 개러지를 먼저 연다
5. 주거지 지오펜스: 데이터가 생기면 `DriveEvent.Quiet`에 연결 (2차)
6. 글꼴(Barlow) 승인, 부품 사진 약관 확인은 M2에서 넘어온 그대로
